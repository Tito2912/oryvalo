# Audit complet — oryvalo.com (2026-04-06)

Périmètre : audit “SEO + technique + contenu + UX/conversion” sur la base du code du repo et d’un contrôle HTTP des pages en production (Vercel) le **6 avril 2026**.

## Résumé exécutif

**Points forts**
- Site **Next.js** déployé sur **Vercel** avec **robots.txt** et **sitemap.xml** en place.
- Pages indexables : **17 URLs** dans le sitemap, **200 OK** (pas de `noindex` détecté), redirections **HTTP→HTTPS**, **www→non-www**, et **slash final** gérées.
- Meta SEO de base propre : **titles** et **descriptions** uniques, **canonical** présent, OpenGraph/Twitter configurés.
- **Headers de sécurité** présents (CSP, HSTS, X-Frame-Options, etc.).
- Pages articles : **JSON-LD** `Article` + `BreadcrumbList` et `FAQPage` quand FAQ renseignée.

**Gros leviers**
- La **home** affiche encore un message “starter” (“Build an online business (SEO-first)”) : impact direct sur **crédibilité**, **CTR**, et **conversion**.
- Les pages **Privacy Policy** / **Affiliate Disclosure** sont trop courtes → risque **confiance** + **conformité** (cookies/analytics/affiliation).
- Manque de signaux **E‑E‑A‑T** (auteur, politique éditoriale, méthode de tests, date & historique de mise à jour).
- Plusieurs articles n’exploitent pas les blocs “Jump links / Quick answer / CTA / FAQ / Next steps” (frontmatter incomplet) → perte de **UX** et de **rich snippets**.

## SEO technique (indexabilité, crawl, duplication)

### Indexabilité & crawl
- `robots.txt` : autorise tout + référence `sitemap.xml`.
- `sitemap.xml` : inclut pages statiques + posts. Les `lastmod` des pages statiques reflètent le build (OK).
- Redirections : `http://` → `https://`, `www.` → racine, et URL avec slash final → sans slash.

### Canonical / meta
- Toutes les pages testées exposent un `<title>`, une meta description et un `rel=canonical`.
- Titles/descriptions : pas de doublons détectés dans le périmètre sitemap.

### Données structurées
- Articles : `Article` + `BreadcrumbList` (et `FAQPage` si `faq` présent).
- À compléter : `Organization` + `WebSite` (site-wide), et champs article plus riches (image, author/publisher logo, etc.).

### Liens internes
- Les liens internes trouvés dans les MDX pointent tous vers des routes existantes (pas de lien interne cassé détecté dans le contenu source).

## Performance & technique

### Points positifs
- CSS simple, peu d’images (logo optimisé via `next/image`).
- Pages pré-rendues côté Vercel (headers `x-nextjs-prerender` observés).

### Points d’attention
- **CSP** actuelle (`script-src 'unsafe-inline'`, `style-src 'unsafe-inline'`) : acceptable pour démarrer, mais pas “durcie”.
- `img-src` n’autorise que `'self' data: blob:` : si vous ajoutez des images externes (CDN, embeds), elles seront bloquées.
- Pas de mesure “terrain” (Core Web Vitals) visible côté code (pas d’analytics / RUM).

## Contenu, UX & conversion

### Home / navigation
- La home est utile comme liste d’articles, mais le hero ressemble à un **template** : à remplacer par une promesse claire + parcours (Start here) + preuve (ex : “0→1” plan, catégories, dernières mises à jour).
- Navigation très courte (2 liens). OK pour minimalisme, mais manque de “hubs” (guides piliers / catégories).

### Qualité éditoriale & E‑E‑A‑T
- “About” trop léger : ajouter qui écrit, pourquoi, comment les recommandations sont faites, et comment les contenus sont mis à jour.
- Les articles “reviews”/affiliation gagnent à afficher une mention d’affiliation **au-dessus du premier lien affilié** (confiance + conformité).

### Frontmatter & composants SEO existants (à exploiter partout)
Le template supporte : `jumpLinks`, `quickAnswer`, `cta`, `internalLinks`, `faq`.
- Articles **sans** ces blocs (à enrichir en priorité) :
  - `ai-video-business`
  - `best-ai-tools-for-beginners`
  - `make-money-with-ai`
  - `how-to-start-an-online-business-no-money`

### Pages légales
- `Privacy Policy` et `Affiliate Disclosure` sont **trop courtes** pour un site avec affiliation (et potentiellement cookies/mesure).
  - Minimum attendu : données collectées, cookies/trackers, partenaires, finalités, base légale (UE), droits utilisateurs, contact, durée de conservation, etc.

## Priorités (recommandées)

### P0 (à faire en premier)
- Refaire le **hero + structure de home** (promesse + parcours + liens vers 2–3 hubs).
- Renforcer **Privacy Policy** + **Affiliate Disclosure** (confiance/conformité).
- Ajouter une section **Editorial policy** / **How we review** + un **auteur** (ou équipe) + “last updated” cohérent.

### P1 (impact SEO/UX rapide)
- Standardiser le frontmatter : `jumpLinks`, `quickAnswer`, `cta`, `faq`, `internalLinks` sur les pages piliers.
- Ajouter `Organization` + `WebSite` JSON-LD en global.
- Ajouter une page “Start here” dédiée (ou renforcer `/online-business-ideas`) + hubs par thématique.

### P2 (scaling)
- Ajouter un **RSS** / feed, et des pages de **catégories** (clusters).
- Mettre en place une mesure : Search Console + (optionnel) analytics respectueux (Plausible/Umami) + objectifs (CTA clicks).
- Process de mise à jour : calendrier + rafraîchissement des posts qui tirent des impressions.

## Plan d’action (concret)

- Légal : étoffer `privacy-policy` + `affiliate-disclosure`.
- Ajouter un bandeau “affiliate disclosure” sur les articles concernés.

**7–14 jours**

- Enrichir 4 posts clés avec `FAQPage` + “Quick answer” + CTA.
- Ajouter `Organization`/`WebSite` schema, et compléter `Article` (image, publisher logo, author page).

**30–90 jours**
- Construire 1 cluster/mois (1 pilier + 6–10 supports + 2 pages commerciales).
- Boucle d’optimisation : titres/intro via GSC (queries 11–20), consolidation des cannibalisations.
